reports 1.13.1 while installed distribution metadata reports 1.13.0. The isolated
wheel consistently reports 1.13.1. Both NumPy builds load OpenBLAS 0.3.29; reference
SciPy uses Intel MKL 2023.1, whereas the isolated SciPy wheel uses OpenBLAS 0.3.27.
Thus the small LR differences are consistent with a numerical-backend/build

Windows native crash and workaround
The initial isolated run with threadpoolctl 3.5.0 terminated with Windows fatal
exception 0xc0000374. The captured stack passes through threadpoolctl Windows
DLL enumeration/_make_controller_from_path/_realpath. Its installed library
paths exceeded 260 characters. The official threadpoolctl 3.6.0 changelog states
support for Windows library paths longer than 260 characters (PR 189):
https://raw.githubusercontent.com/joblib/threadpoolctl/3.6.0/CHANGES.md
https://github.com/joblib/threadpoolctl/pull/189
This mechanism and the stack support the long-path diagnosis. With threadpoolctl
3.6.0 and reference joblib 1.4.2, all 20 primary model fits completed without that
native crash, followed by the ordinary Python strict-comparison AssertionError
described above. Scientific analysis code and model parameters were unchanged.
Requirements now select the documented threadpoolctl fix. A successful native
run and agreement in reported metrics are distinct from passing strict replay.

Scope
This isolated-environment test covers the four-model primary seed-42 run only.
It is not proof that all repeated/identity/status/taxonomy runs reproduce in this
different backend. All five modes separately reproduced exactly in fresh copies
under the original existing runtime. No additional training was needed for this
cross-backend comparison, and no comparison tolerance was relaxed.

Artifacts
comparison_summary.json retains strict_probability_comparison=FAIL. CSVs show
every probability comparison, score-order changes, every metric comparison,
independent reconstruction, exact-ranking comparison and runtime provenance.
Export-schema normalization only reconciles column names, adds independently
calculated pooled classifications where absent, and calculates pooled-minus-mean;
it is documented in export_schema_normalization.csv. Raw tables are unchanged.

The portable bundle includes compare_clean_backend.py and copied clean outputs.
From the bundle, regenerate this read-only comparison with:
    python compare_clean_backend.py --reference reference/seed42 --clean validation/clean_environment/seed42 --out cross_backend_rerun
That diagnostic writes a FAIL result but returns normally after completing its
analysis. To reproduce the original strict assertion as a nonzero exit, add:
    --assert-strict
The default training CLI still enforces the original strict comparison. In this
clean backend it exits with that expected assertion after saving primary results;
the failure must not be interpreted as bitwise or strict numerical reproduction.
